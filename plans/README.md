## Findings considered and rejected

- A Ship Studio-only component file format was rejected because it would fork
  the user's application away from its framework and make source code cease to
  be the authority.
- Rendered-DOM pattern matching was rejected as a component detector because
  compilation erases component boundaries and repeated DOM is not proof of a
  reusable source component.
- Depending on a Node.js installation in the user's project was rejected. The
  component parsers must ship with Ship Studio and run without executing the
  project's dependencies or configuration.
- Universal “unlink instance” behavior was rejected. Expanding an arbitrary
  React, Vue, Svelte, Astro, Liquid, React Native, or Flutter component into
  equivalent static source is not generally semantics-preserving.
